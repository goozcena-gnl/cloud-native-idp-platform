# GitOps with ArgoCD (Task 1.3)

This task installs ArgoCD into the `argocd` namespace using the
`argo/argo-cd` Helm chart. ArgoCD will become the GitOps reconciler for the
platform. This is the bootstrap phase, so a manual Helm install is acceptable.

## Design

| Aspect | Choice |
|---|---|
| Chart | `argo/argo-cd` |
| Namespace | `argocd` |
| Service type | ClusterIP only |
| Public exposure | None |
| Local access | `kubectl port-forward` only |
| SSO (Dex) | Disabled |
| Server TLS | Insecure HTTP (local only, behind port-forward) |

ArgoCD is intentionally not exposed through Ingress, NodePort, or
LoadBalancer. The only access path is a local port-forward.

### Why `server.insecure: "true"`?

For this local MVP, ArgoCD is accessed only through `kubectl port-forward`.
The ArgoCD API server can run with TLS disabled by setting
`server.insecure: "true"` in the command parameters ConfigMap generated by
the Helm chart. This avoids browser TLS warnings during local-only bootstrap.

This is acceptable only for local development. Do not use insecure HTTP for
shared, remote, or production clusters.

## Prerequisites

- kind cluster `idp-local` is running.
- The `argocd` namespace exists (`./scripts/apply-platform-namespaces.sh`).
- Helm and kubectl are installed.
- Docker Desktop is running.

## Install ArgoCD

Run from the repository root:

```bash
./scripts/install-argocd.sh
```

The script is idempotent (`helm upgrade --install`). You can re-run it safely.

To pin or change the chart version:

```bash
CHART_VERSION=9.5.21 ./scripts/install-argocd.sh
```

## Validate

```bash
kubectl -n argocd get pods
kubectl -n argocd get svc
helm -n argocd list
helm status argocd -n argocd
```

Expected results:

- ArgoCD Deployments and the application-controller StatefulSet become ready.
- Long-running ArgoCD pods reach `Running` / `Ready`.
- The Redis secret init hook pod may show `Completed`; that is expected.
- The `argocd-server` service type is `ClusterIP`.
- No LoadBalancer or NodePort services exist in the namespace.

## Repository Access Check

Before creating ArgoCD `Application` resources, confirm the Git repository URL
and visibility:

```bash
./scripts/check-gitops-repo.sh
```

Use the printed recommended `repoURL` for future Applications. If the
repository is private, configure ArgoCD credentials outside Git before creating
Applications. Do not commit repository credentials or ArgoCD repo Secret
manifests containing secret material.

For the MVP, the preferred model is a public GitHub repository, an HTTPS
`repoURL`, and no committed credentials. If the repository is private, stop
before creating ArgoCD Applications and configure repository credentials
securely outside Git.

See [GITOPS_REPOSITORY.md](GITOPS_REPOSITORY.md).

## Private Repository Access

This project currently uses a private GitHub repository, so ArgoCD requires
read credentials before it can reconcile Applications from Git.

Configure ArgoCD read access with:

```bash
./scripts/configure-argocd-private-repo.sh
```

Validate the Secret structure without printing the token:

```bash
./scripts/check-argocd-repo-secret.sh
```

The GitHub token must never be committed to Git.

## Local Access

Start a local port-forward in a dedicated terminal:

```bash
./scripts/argocd-port-forward.sh
```

Then open:

```
http://localhost:8081
```

Stop access with `Ctrl+C`. Closing the terminal also ends the forward.

## Initial Admin Password

ArgoCD generates an initial admin password into a Kubernetes Secret.

Retrieve it (Git Bash):

```bash
kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d; echo
```

Log in with:

- Username: `admin`
- Password: the value printed above

### Rotate and remove the initial secret

After your first login, change the admin password in the UI or via the
ArgoCD CLI, then delete the bootstrap secret:

```bash
kubectl -n argocd delete secret argocd-initial-admin-secret
```

## Security Warnings

- Do not expose ArgoCD publicly. Keep it ClusterIP + port-forward only.
- Insecure HTTP is enabled for LOCAL use behind port-forward. Never use this
  mode for shared, remote, or production clusters.
- The initial admin secret is bootstrap-only. Rotate the password and delete
  the secret after first login.
- Do not commit any ArgoCD secrets, tokens, kubeconfig files, or exported
  credentials.
- Treat the ArgoCD admin account as highly privileged. It can deploy and
  delete workloads across managed namespaces.

## GitOps Transition Principle

Before ArgoCD is installed, manual bootstrap is acceptable. After ArgoCD is
running, Git should become the source of truth. Manual cluster changes should
be limited to emergency debugging and reconciled back into Git afterward.

## Debugging

### Pods not becoming Ready

```bash
kubectl -n argocd get pods
kubectl -n argocd describe pod <pod-name>
kubectl -n argocd logs deploy/argocd-server
```

- On local kind, allow time for image pulls on first install.
- Check Docker Desktop has enough memory if pods are `OOMKilled`.

### Port-forward fails or the UI does not load

- Confirm the server pod is Ready:

```bash
kubectl -n argocd get pods -l app.kubernetes.io/name=argocd-server
```

- Confirm the service exists and is ClusterIP:

```bash
kubectl -n argocd get svc argocd-server
```

- Ensure local port `8081` is free, or override it:

```bash
LOCAL_PORT=9090 ./scripts/argocd-port-forward.sh
```

### Login fails

- Re-read the initial admin password (see above). Ensure no trailing newline
  was copied.
- If you already rotated the password, use the new one.
- If the initial secret was deleted and you forgot the password, reset it via
  the ArgoCD CLI or by patching the `argocd-secret` admin password hash.

### Context mismatch

The scripts refuse to run on the wrong cluster:

```bash
kubectl config get-contexts
kubectl config use-context kind-idp-local
```

### Clean reinstall

```bash
helm -n argocd uninstall argocd
kubectl -n argocd delete secret argocd-initial-admin-secret --ignore-not-found
./scripts/install-argocd.sh
```
